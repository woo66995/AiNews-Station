# AiNews 情报站 - 采集与处理算法文档

本文档总结了 AiNews 网站目前所使用的新闻采集源、采集频率、处理机制以及评分/算法规则。

## 2. 采集频次与时间流转 (Timing & Frequency)

Worker 通过 Cloudflare Cron Triggers 进行调度：

- **内容抓取 (Fetch Cycle)**：每 4 小时执行一次 (`0 0,4,8,12,16,20 * * *`)。
  - 从所有数据源拉取最新文章。
  - 使用 URL 进行数据库去重（`deduplicateArticles`）。
  - 将新文章插入数据库，状态设为 `pending`。
  - **受限处理**：为避免 Gemini 免费 API 超额，每次运行仅从 `pending` 队列中提取 **10 篇**文章交由大模型进行总结翻译（每两次请求间硬性延迟 5 秒）。
  - **随机发布时间 (`scheduled_at`)**：翻译完成的文章不会立刻发布，而是被赋予一个随机的 `delayMs`（0 到 4 小时之间），状态设为 `scheduled`。

- **内容发布 (Release Cycle)**：每 15 分钟执行一次 (`*/15 * * * *`)。
  - 检查数据库中 `scheduled_at <= 当前时间` 且状态为 `scheduled` 的文章。
  - 将它们的状态更新为 `done`。
  - 通过 Telegram Bot 推送到指定频道。
  - *(在此前的某个版本中，还会通过 webhook 触发 Cloudflare Pages 重新构建)*。

- **每日速览 (Daily Digest)**：
  - 每天推送两次：北京时间早上 8:00 - 9:59 (UTC 0-1) 及晚上 20:00 - 21:59 (UTC 12-13)。

## 3. 采集规则与过滤算法 (Algorithm Rules)

为了确保信息噪音最小化，采集过程有严格的过滤和排序机制：

### 3.1 时效性过滤
- 系统会主动过滤掉发布时间 (`published_at`) 超过 **7 天** 的旧文章，确保新闻的绝对时效性。

### 3.2 关键词匹配过滤 (Keyword Filtering)
- **官方博客豁免**：来自 OpenAI、Anthropic、Cursor 等官方渠道的内容**无需过滤**，默认全部入库。
- **社区与媒体过滤**：对于 Reddit、V2EX、TechCrunch、The Verge 等泛科技/综合社区的数据源，系统要求文章的标题或摘要**必须包含以下 AI 关键词之一**，否则直接丢弃：
  > `ai`, `llm`, `gpt`, `claude`, `gemini`, `openai`, `anthropic`, `cursor`, `copilot`, `agent`, `mcp`, `model`, `mistral`, `deepseek`, `coding`, `transformer`, `diffusion`, `neural`, `machine learning`, `ml`, `inference`, `embedding`, `rag`, `langchain`, `ollama`, `windsurf`, `codeium`, `replit`, `token`, `prompt`, `fine-tun`, `vibe`, `agentic`, `大模型`, `人工智能`, `大语言`, `白嫖`, `免费`, `薅羊毛` (等)

### 3.3 大模型翻译与内容重构 (AI Summarization)
被选中的文章会通过 Google Gemini 3.5 Flash 进行深度处理：
- **标题汉化**：生成 20 字以内的中文标题，准确传达核心信息。
- **正文摘要**：提取原文前 4000 字内容，生成 200-350 字的结构化摘要（包含核心技术实现、主要背景、关键结论及实际影响）。
- **分类与标签打标**：AI 自动为文章分配 `coding`, `agent`, `model`, `tool` 等类别，并提取最多 5 个英文小写标签以供前端生成趋势云图。

### 3.4 优先级与排序逻辑 (Sorting)
在最新修复的系统中：
1. **排队处理优先级**：目前系统按 `fetched_at DESC` 的顺序从 `pending` 队列抽取新闻交由大模型处理。
2. **网站前端排序**：网页接口（API）返回文章的顺序为：`ORDER BY COALESCE(scheduled_at, published_at, fetched_at) DESC`。
   - 这意味着，无论文章的原始发布时间是多久之前，**它被 AI 处理完成并在网站上正式发布的时间 (`scheduled_at`)** 将作为它在网站流中的绝对顺位。
   - 这样保证了前端的展示顺序与 Telegram 推送顺序一致，新处理的内容永远置顶。
